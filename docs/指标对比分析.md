## 三、重点问题分析

### 问题 1：RAG 准确率（0.40）为何低于 BASELINE（0.60）？

**根本原因：大量检索失败导致系统性偏向输出 NEI。**

从 RAG 详细结果中可以看到，evidnce 字段大量出现：
- `检索错误: Expecting value: line 1 column 1 (char 0)`（Wikipedia API 网络请求返回空响应）
- `未找到有效证据。`（关键词提取后 Wikipedia 搜不到相关页面）

在 50 条样本中，RAG 共输出 **36 次 NEI 预测**（占 72%），而 BASELINE 只有 6 次 NEI 预测。这说明：

- 当检索失败时，LLM 看到错误信息而非有效证据，保守地输出 NOT ENOUGH INFO
- 21 条真实 SUPPORTS 中有 **15 条（71%）被错误预测为 NEI**
- 14 条真实 REFUTES 中有 **9 条（64%）被错误预测为 NEI**

结果是一个表面矛盾的现象：RAG 的 NEI 召回率反而达到 0.80（BASELINE 仅 0.067），但这不是"模型学会识别信息不足"，而是**检索失败的副产品**。真实 SUPPORTS/REFUTES 的召回率暴跌至 0.24/0.21，拖垮了整体准确率。

**附：关键词提取也带来噪声**。RAG 使用 LLM 提取 1-2 个关键词再搜 Wikipedia，提取结果有时完全偏离：
- "Matt Bomer's first middle name is Staton" → 检索到 Linda Lavin 的页面
- "Pharmacology deals with...turnips" → 检索到 Potassium in biology
- 即便成功检索，摘要句也不一定包含判断所需的精确事实

> **结论：RAG 在本实验中的失败主要是工程问题（网络不稳定 + 关键词提取偏差），而非 RAG 方法论的失败。**

---

### 问题 2：RAG_BM25 幻觉率（0.5333）为何高于 RAG（0.20）？

**表面矛盾，实质是"可靠检索带来的自信心副作用"。**

| | 15 条真实 NEI 中 |
|-|----------------|
| RAG | 3 条预测为 SUPPORTS/REFUTES（幻觉）= 20% |
| RAG_BM25 | 8 条预测为 SUPPORTS/REFUTES（幻觉）= 53% |

**RAG 幻觉率低的真实原因**：大量检索失败 → 模型看到错误信息 → 默认输出 NEI → 对真实 NEI 碰巧"判断正确"，属于被动正确。

**RAG_BM25 幻觉率高的真实原因**：本地 BM25 检索可靠，每条 NEI claim 都能检索到与实体主题相关的 Wikipedia 句子。但 NEI 类型的 claim 在 FEVER 中的定义是"现有证据无法确定真伪"，而 BM25 检索到的内容虽然主题相关，却可能使模型错误地作出判断。典型案例：

- id 78882（"Francis I and Charles V were rivals..."，真实：NEI）  
  → BM25 检索到"Francis I... was known for his personal involvement in the wars against his great rival...Charles V"  
  → 证据直接点明两者确为"rival"，模型输出 SUPPORTS（幻觉）

- id 132124（"James VI opposed British colonization..."，真实：NEI）  
  → BM25 检索到"In his reign, the Plantation of Ulster and British colonization of the Americas began"  
  → 证据显示殖民在其统治期间发生，模型推断他支持而非反对，输出 REFUTES（幻觉）

**本质**：对于 NEI 类型的 claim，FEVER 的"信息不足"往往不是说 Wikipedia 上没有相关信息，而是说标注者认为现有证据不够确凿。BM25 检索到"相关但不直接"的内容，反而让 LLM 过度自信地作出判断，产生幻觉。

> **RAG（低幻觉）≠ 好模型，RAG_BM25（高幻觉）≠ 差检索。两者的幻觉率差异主要来自检索可靠性差异，而非 NEI 识别能力的本质区别。**

## 四、其他显著对比

### 4.1 COT vs BASELINE：推理链的边际收益有限

| 指标 | BASELINE | COT | 变化 |
|------|:--------:|:---:|:----:|
| Accuracy | 0.60 | 0.64 | +4% |
| Macro F1 | 0.5016 | 0.5573 | +5.6% |
| 幻觉率 | 0.9333 | 0.8667 | -6.7% |
| SUPPORTS F1 | 0.7556 | 0.8182 | +6.3% |
| NEI F1 | 0.1176 | 0.2222 | +10.5%（仍极差）|

CoT 强制分步推理后，SUPPORTS/REFUTES 的识别略有改善（逻辑链更严谨）。但对 NEI 类 claim 的识别几乎无效：NEI recall 从 0.0667 仅升至 0.1333（15 条中只多猜对 1 条）。

CoT 和 BASELINE 都有一个共同缺陷：**无外部证据时，LLM 倾向于把模糊声明强行划分为 SUPPORTS 或 REFUTES**，即使事实并不确定。这是两种模式高幻觉率（90%+）的根本原因。

### 4.2 RAG_COT vs RAG：CoT 缓解了检索失败带来的 NEI 偏置

| 指标 | RAG | RAG_COT | 变化 |
|------|:---:|:-------:|:----:|
| Accuracy | 0.40 | 0.50 | +10% |
| Macro F1 | 0.3718 | 0.4980 | +12.6% |
| 幻觉率 | 0.20 | 0.4667 | +26.7% |
| SUPPORTS Recall | 0.2381 | 0.5238 | +28.6% |
| NEI Recall | 0.8000 | 0.5333 | -26.7% |

RAG_COT 相比 RAG，SUPPORTS/REFUTES 的召回率显著改善：当检索到有效内容时，CoT 引导模型更充分地利用证据做出判断，而不是因为证据有限就立刻输出 NEI。这部分弥补了 RAG 的"过度默认 NEI"问题，但同时也把幻觉率从 0.20 拉高到 0.4667。

### 4.3 RAG_BM25 vs RAG：本地检索全面碾压在线检索

| 指标 | RAG | RAG_BM25 | 变化 |
|------|:---:|:--------:|:----:|
| Accuracy | 0.40 | 0.66 | **+26%** |
| Macro F1 | 0.3718 | 0.6397 | **+27%** |
| SUPPORTS Recall | 0.2381 | 0.8095 | **+57%** |
| REFUTES Recall | 0.2143 | 0.6429 | **+43%** |
| LLM 调用次数/条 | 2次 | **1次** | 减少50% |

RAG_BM25 在同一数据集上（同样的 50 条 dev claims）全面超越 RAG，且不需要关键词提取（节省一次 API 调用）。这主要是因为：
1. **检索可靠**：本地 dump 无网络失败，每条 claim 必然返回证据
2. **检索精准**：BM25 直接用完整 claim 检索，证据来源与 FEVER ground-truth 相同的 Wikipedia dump
3. **句子级证据**：返回 Top-5 精确句子（+来源标注），比 Wikipedia API 摘要更具体

RAG_BM25 也是五组常规模式中**唯一 Precision=Recall=F1**（均为 0.6397）的模式，说明检索质量的均匀性使三类标签的预测置信度趋于一致。

### 4.4 RAG_GOLDEN vs 其余模式：证据质量决定性能上界

RAG_GOLDEN 的 Accuracy=0.96、幻觉率=0.00，与其余五组形成断崖式差距。

这个结果的核心含义是：**LLM 的推理能力本身是足够的，性能瓶颈完全在于证据质量**。  
当证据是 FEVER 标注者手工指定的 ground-truth 原句时，DeepSeek 几乎可以完美判断；  
当证据来自有噪声的检索（RAG/RAG_BM25），或根本没有证据（BASELINE/COT），性能就大幅下降。

仅有的 2 例错误（1 例 SUPPORTS→REFUTES，1 例 REFUTES→NEI）分析：
- id 198393（"Marilyn Manson was formed by the singer Marilyn Manson"）：证据说"formed by singer Marilyn Manson and guitarist Daisy Berkowitz"，模型关注"不是唯一创始人"而输出 REFUTES（claim 说"by the singer"，其实也是事实之一，算 SUPPORTS）
- id 22707（"Kirk Douglas is a singer"）：证据说"is an American actor, producer, director, and author"，没有直接写"not a singer"，模型谨慎输出 NEI（正确应为 REFUTES）

## 五、综合结论

```
性能排序（Accuracy）：
RAG_GOLDEN(0.96) >> RAG_BM25(0.66) > COT(0.64) > BASELINE(0.60) > RAG_COT(0.50) > RAG(0.40)

幻觉率排序（越低越好）：
RAG_GOLDEN(0.00) < RAG(0.20*) < RAG_COT(0.47) < RAG_BM25(0.53) < COT(0.87) < BASELINE(0.93)
* RAG 低幻觉是检索失败的副产品，非真实能力
```

| 关键结论 | 支撑证据 |
|---------|---------|
| 检索可靠性 > 检索方式 | RAG_BM25 vs RAG：同为检索增强，本地稳定检索比在线不稳定检索高出 26% accuracy |
| 证据质量 >> LLM 推理能力 | RAG_GOLDEN 96% vs 最好的常规模式 66%，差距来自证据，不来自推理 |
| NEI 是最难识别的类别 | 所有非 Golden 模式中，NEI F1 均为最低类；BASELINE/COT 幻觉率 90%+ |
| CoT 对检索增强帮助有限 | RAG_COT 准确率 0.50 < RAG_BM25 的 0.66，在可靠检索下更高效 |
| 低幻觉不等于好检索 | RAG 幻觉率低是检索失败的偶然结果，RAG_BM25 更高幻觉率是"有勇气作决定"的表现 |
